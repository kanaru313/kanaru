# Design guidelines

UI rules as the code implements them today. New screens follow these first; if a rule is wrong for a new case, change the rule here in the same PR.

Related: [code-standards.md](./code-standards.md) (widget conventions), [features.md](./features.md) (requirements by ID).

## Principles

1. **Material 3 everywhere.** Use `material_ui` widgets and theme tokens. No hard-coded colors for text or surfaces. One exception: an icon drawn over a darkened image (scrim or black overlay) is white, since it sits on an image and not on a theme surface, e.g. the Now Playing cover button and the playing song row's cover. On the playing row every other icon follows `onPrimaryContainer`, including the unliked heart (a liked heart keeps `primary`).
2. **Library first, player always.** Browsing works without playback; playback controls are visible on every screen where a track can be playing.
3. **Works from the 480 px minimum window to a 4K display.** Layout changes at named breakpoints, not by device type. UI-05 targets 360 px, which is not yet the minimum.
4. **Keyboard and mouse are both first class.** Every action has a key or a visible control; overlays restore focus on close.
5. **Calm motion.** Animations are short and skipped under reduced motion.
6. **Say what is happening.** Empty, loading and "updating" states name the situation (see [States](#states)).

## Shell layout

| Width | Sidebar | Top bar | Player bar |
|---|---|---|---|
| >= 720 px | Column: 240 px, or 72 px icon rail after collapse | 64 px; back, forward, search, Settings | 96 px, full width under the page |
| < 720 px | Drawer, opened from the top bar | 64 px; back, search, Settings | 96 px, compact layout with a seek strip |

The banner `PlaybackUnavailableBanner` sits under the top bar when the audio engine is off (library-only mode). The page fills the rest.

- **Sidebar.** Groups: Home | Songs, Albums, Artists, Genres, Languages, Folders | Playlists, Favorites, Queues, History, Most played. The library group (Songs to Folders) is hideable: Settings → Interface has one chip per tab (at least one stays on), and it applies to the column, the rail and the drawer; on the page of a tab just hidden the user stays and no row is lit. Home and the third group are always shown. Languages (`/languages`) sits right after Genres. There is no "Current queue" row: the queue sheet opens from the queue button of the player bar. Queues (`/queue-history`, the page that lists saved queues; the URL keeps its old name) lists the queues the user replaced, newest first: collage, when it was saved (date and time in the user's language), song count, a Play button and a menu (Play, Shuffle, Play next, Add to queue, Save as playlist, Delete with confirmation; also on right click, long press and the menu key). A row opens the saved queue at `/queue-history/:id` with the playlist entries view (play from a song, queue menu, export, drag and remove). Playlists is an ordinary row at the top of the third group. It opens `/playlists` through the shell's branch switch like any destination (back to the last playlist page, or the grid when already there) and is highlighted on the grid and on every playlist page (`/playlists/<id>`). The sidebar lists no playlists and has no create button: playlists are listed and created on the Playlists page. Collapses between 240 px and 72 px in 400 ms. A tooltip names each icon in rail mode.
- **Top bar.** 64 px. Back and forward (forward and back hidden below 560 px), search field, Settings on the right at every width. Empty space drags the window.
- **Live search.** Typing opens `/search?q=…` 150 ms after the last keystroke; Enter opens it at once. Consecutive searches replace one history entry, so Back returns to the page before the search. Leaving the search page clears the field; Back or Forward onto a search restores its text from the URL.
- **Search history.** While the field has focus and is empty, the last searches (up to 20) list in a panel under it, at least 280 px wide, eight rows before it scrolls. A row has a history icon, the query and a remove button; "Clear all" ends the panel. Choosing a row (click, or Up/Down and Enter) fills the field, opens the search and moves the query to the top. Typing, Esc, losing focus or removing the last row closes the panel; the buttons never take focus from the field. A query is saved on Enter, on choosing a suggestion and on opening a result on the search page, not on each keystroke.
- **Custom title bar.** Window buttons appear only when the title bar setting is `kanaru`. Settings says the change needs a restart.
- **Reselecting a sidebar item** returns that branch to its root.
- **History.** Browser-style back and forward with a 100-entry cap. Mouse back and forward buttons work at any width.

## Player bar

- Height 96 px. Shows artwork, title and artist, transport (previous, play or pause, next), seek bar, volume, shuffle, repeat (a button that opens the repeat menu), and the queue button.
- Below 720 px: compact layout with a thin seek strip on the top edge. Controls stay in the bar.
- Shown when a queue exists (`playerBarVisibleProvider`).
- Seek bar: a straight track like the volume slider: played part in primary, a gap, an upright pill thumb, a gap, the rest in secondaryContainer. It does not animate while playing; it follows playback in pixel-sized steps (250/500/1000 ms). The player bar, the compact strip and the narrow Now Playing page keep this flat track. The wide Now Playing modes show the track's waveform instead (it can be turned off in Settings -> Appearance, "Waveform seek bar"; the slot then shows the flat track in 24 px and the cover or lyrics get that room back): mirrored rounded bars (3 px wide, 2 px apart, 1.5 px radius, 2 to 32 px high, centered in a 48 px track), played bars in primary at 85 % opacity, the rest in primary at 35 % opacity, an upright 4 x 36 px primary pill thumb (shorter than the track) with a cleared band of 6 px on each side. Bar heights follow the track's own range: the levels are stretched before drawing (the quietest tenth to the shortest bar, the loudest percent to the tallest), and a bar shows the mean loudness of its time range. Bars map time against the player's duration. Until the waveform is ready, and for files with none (Opus, APE, WavPack, unreadable), the flat track shows in the same 48 px; when data arrives later the bars fade in over it. Hover bubble, click and drag seek, and the arrow keys are the flat track's.
- Volume: hover popup that hides itself: only the vertical slider, with no card behind it and no percent. Scroll wheel changes volume (PLAY-04).
- Repeat menu (QUEUE-05): the repeat button toggles a `MenuAnchor` (no cycling) with five items, the active one on `secondaryContainer`: stop after the last song (`playlist_play`), repeat the current song (`repeat_one`), repeat N more times (circled number, with inline - and + that keep the menu open; N is 1 to 99, the draft starts at 1; the item and - / + are disabled while playback is stopped), repeat the whole queue (`repeat`), repeat the whole queue shuffled (`repeat` with a small shuffle glyph). The button shows the active mode's icon and its label as tooltip, lit unless the queue stops at its end, and is disabled with an empty queue. Ctrl+R still cycles off, all, all shuffled, one.
- Sleep timer (PLAY-14): timer button left of volume. Outlined while off; filled in primary with a short label (`m:ss`, `h:mm:ss`, or Track/Album/Queue) while on, dimmed while counting is held. The label shows only from a 1280 px window; the tooltip always has the full text. The button is left out below about 900 px (the controls column keeps its width); the compact layout shows the icon only, with no label. When the timer button appears, the controls column steps down by 96 px (48 px per side) to make room. The menu (`MenuAnchor`) lists presets, Custom… and the end-of modes; while on it adds a header, +/- 5 minutes, pause or resume counting, and cancel.
- Icon buttons carry tooltips.
- Text links (artist and album names): `HoverUnderlineLinks`, no icon, no ink. Underline only the hovered link on hover (drawn 3 px lower than a normal underline: the line is painted as transparent text with an upward-offset shadow and the whole line is translated down 3 px, so glyphs stay put), all links of the line on keyboard focus; separators stay plain text and are not clickable. Each link opens its own page; in the Now Playing artist line Enter (one Tab stop for the line) asks which artist when the song has several, and a tag whose names cannot be found in it is one link that asks too.

## Queue sheet

- A panel on the right, at most 440 px wide, in a solid `surfaceContainerLow` (nothing shows through). The scrim and the panel end at the top of the player bar, which stays visible and clickable. Not a route; the mouse back button closes it, and Esc closes it from anywhere, also when a click moved focus to a bar control (a bar menu opened with the mouse does not hold focus, so Esc closes the sheet and leaves that menu open until a click; the queue's own `⋮` menu closes with the sheet). Opening Now Playing closes it. Focus returns on close.
- Header in two rows: the title "Now playing" with the close button, then a summary line ("876 tracks · 3 h 12 min left", or only the count under repeat or when a track has no known duration; rounded up to minutes, rebuilt once per minute) with the filter and a `⋮` menu (Save queue as playlist, Clear queue; each greyed out when it cannot run). The `⋮` button has an explicit accessible name.
- The queue button in the player bar toggles the sheet: pressed while it is open it closes it, is shown selected and its tooltip says "Close". Its count badge uses `secondaryContainer`, not the error color.
- Rows are the Songs row (`SongRowView`, a rounded card at least 88 px with its gap): a drag handle, the 64 px cover, title, artist, "album • year", the duration above a heart, and a remove button at the end that shows on hover or keyboard focus (it also has a screen-reader action). Every row drags, the playing one too; rows above the playing one are dimmed. The current row (by position, so a file queued twice lights once) has the playing-song colors: `primaryContainer` card, `onPrimaryContainer` text and icons, an equalizer on its cover, also while paused (`queue_tile.dart`). Rows in the play-next block right after it carry a 3 px `tertiary` bar on their left edge (a corner radius short of the card's top and bottom, clear of its rounded corners) and read "Play next" to screen readers. Covers and labels are those of the moment the track was queued; a queue restored from an old session has no album line. The row menu (right click, long press, Menu key) lists Play next (a move of the row behind the play-next block, never a copy; hidden on the playing row and on play-next rows), Add to playlist…, Add to or Remove from favorites, Find lyrics online…, Show artist, Show album, Show in folder, Show in file manager and Remove from queue. A song outside the library has no playlist, Add to favorites or artist and album links (it keeps Remove from favorites when it is a favorite), and a stream has no file manager row. Add to queue is not offered here. Find lyrics online… is shown for any local file while the library is open, tagged or not, also for a song outside the library; the song menu of Songs, Home and other lists has the same row after its Favorites row. It opens the Choose lyrics dialog (`lib/shared/lyrics_picker/`): wide windows only, a 840 px width and a height of 85 % of the window up to 720 px (never under 440 px; a smaller window scrolls), a query field prefilled with "artist title" (empty for a song without tags; a song with an artist but no title shows only the artist and waits for Search; a placeholder artist such as "Unknown Artist" is never filled in; with the note "Type the artist and title, then press Search" in place of the results, Search off while the field is blank, and nothing sent until the user searches), a one-or-two-line "Song:" subtitle that ends in an ellipsis, a result list (the source's name first in each result's detail row, with the author where two sources share a name; badge Synced, Plain or Instrumental; length difference over 3 s in the error color; "Good match"; above it one failure line per source that failed, with Retry and, for a plugin whose log file exists, View log; narrowed by the source filter in the search row) beside a preview pane, and Cancel / Use these lyrics. The search row reads `[source chip ▾] [query field] [Search]`: the chip is 200 px wide, so the field never moves, and opens a dropdown menu with "All sources" (total count) and one item per source that returned results (its count; a check marks the current one; names wrap, never ellipsized). Unfiltered it reads "All sources (n)" on a surface with an outline; filtered it shows the source name on `secondaryContainer`, and a name wider than the chip scrolls back and forth (`LyricsPickerMarqueeLabel`) while the pointer hovers it or the keyboard has focus on it, with the full name as tooltip. With fewer than two sources the chip is disabled and reads "All sources"; every search starts again at All. The preview of synced lyrics has a time column before the text (`mm:ss.xx`, `h:mm:ss.xx` from one hour; monospace in `onSurfaceVariant`; a wrapped line stays under the text; an empty line shows its time and a dim ♪); plain lyrics show text only.
- A small tonal arrow button floats at the bottom right of the full list while the playing row is entirely out of view (up or down, toward the row; same label and action as the header jump button, fades in 150 ms, none under reduced motion). It is not in the tree otherwise, and it hides during a drag, in the filter, and in a queue of one row. The list keeps 72 px of bottom padding so the last row can scroll clear of it.
- A search button at the end of the summary line grows a filter box leftwards over the summary, as on the album page, and turns into a close button (`Ctrl+F` reaches it while the sheet is open, Esc closes the box first). Matches are the real rows, best match first, without drag handle or remove button; tapping one jumps to it and leaves the queue as it is. Closing the sheet drops the filter.
- Opens and closes in 400 ms.

## Library screens

Songs opens as a list by default; the other pages opened from the sidebar (Artists, Genres, Folders, Languages) open as a grid; a switch to the list is remembered for the session only.

The Languages tab lists the languages named by the language tag as round tiles (name and song count), sorted by code; a language page has Play, Shuffle, its albums and its songs like a genre page, and the tab's empty state says the tags come from `TLAN` or `LANGUAGE` and that a rescan reads them.

| Screen | Layout |
|---|---|
| Songs | Virtualized list (the default), one row per track, read in pages of 200; or a grid of cards (`SongGridTile`: radius 12, 8 px between cards, tinted via `songCardColor`), each with an inset rounded cover (radius 8, 4 px from the card's edges and top) carrying a heart chip at its bottom-right, then a bold title, the artist and "album • length" (text 12 px from the card's edges, 12 px of padding under it); covers sit 32 px from the page edge. The playing tile has a `primaryContainer` card, `onPrimaryContainer` texts and no equalizer. Read the same way. The header button switches them per session (not kept across restarts) and a switch starts at the top. Tap plays the list from that song in the displayed order; right click opens the song modal in both (a card has no ⋮ button). A list row (`SongTile`, also on search, Home lists, folder, artist, genre, language and playlist pages) is a rounded card (radius 12, 16 px from the list edges, 8 px between cards), at least 88 px with its gap (`songCardExtent` gives the exact height at the text scale; `songCardColor` sets the tone, a faint veil of `onSurface`; `SongTile` wraps the provider-free `SongRowView`): a 64 px cover, then the title (semi-bold), the artist and "album • year", then the duration above a heart that likes or unlikes the song. ## Search page

Opens from the top bar at `/search?q=…`. An empty query shows "Search your library".

- **Sections** in order: Songs, Albums, Artists. A section without matches is hidden. Its header shows the count of all matches.
- **Rows.** Eight per section. A longer section has one toggle below its rows: "Show all (N)", or "Show top N" for songs when more than the 200 loaded songs match. "Show less" closes it in place.
- **Songs hint.** Once the songs are expanded and more match than are shown, a line says how many are shown and asks for more words.
- **Song tap** plays only that song (a queue of one). Right-click or long-press opens the queue menu (Play next, Add to queue, Add to playlist…).
- **Album and artist rows** open their pages. They have no queue menu.
- **States**, checked in this order: library unavailable; no folders; "Updating library" while keys are recomputed; loading; "Search failed" (previous results stay only while a newer query loads); no results. While the first scan runs and there are no results yet, the page shows loading instead of "No results".
- Results follow rescans while the page is open.
- **Syntax.** The query accepts `artist:`, `album:`, `genre:` (words in that field), `year:2010`, `year:>2010`, `year:<2000`, `year:2010-2015`, `format:flac` and `language:vi` (matches by language key, so `vi`, `vie` and `Vietnamese` are the same; several are alternatives; untagged songs never match); a value with spaces goes in double quotes. Unknown prefixes and broken values count as plain words. The filters and the field prefixes apply to the Songs section only. Albums and Artists use only the plain words. A query with only filters (`year:2010`) lists songs and no other section.
- **Field picker.** A "Search fields" button sits in the page header, also when the query is empty. It opens a menu with two presets ("All fields", "Titles only"), a divider and one checkbox per field: title, artist, album, album artist, genre, file name, description. The menu stays open while fields are toggled. The last field cannot be turned off. A dot and the label "Search fields (filtered)" show that the choice differs from "All fields"; on a narrow header the button is an icon with a tooltip. The choice is saved with the search history and kept across restarts. Lyrics are not offered.
- **Sections follow the fields.** Albums need plain words and the album or album artist field; Artists need plain words and the artist field. Until the saved choice has loaded the page uses "All fields". When nothing matches and the fields are not "All fields", the message also suggests turning on more fields.
- **Corrected query.** When part of the results come from a typo-fixed query (fewer than 5 songs matched as typed), a muted line “Results for “…”” sits above the first section. It shows the query with the fixed words replaced; syntax is kept. Without such results no line shows, and a query with no results at all keeps the plain “No results” state.
- **History.** The query as typed (syntax included) is saved when the user opens a result from this page: plays or queues a song, opens an album or an artist. Typing alone saves nothing.

## Lyrics plugin store

Feature code: `lib/features/lyrics_plugin_store/`. The pages take callbacks (`onOpenInstalled`, `onOpenCatalogItem`, `onOpenRepositories`) and never navigate themselves; the router mounts the routes, and the route paths are in `lib/shared/lyrics_source_routes.dart`. Opened from the "Plugin store" button of the Sources page (`/settings/lyrics-sources/store`); repositories at `/settings/lyrics-sources/store/repositories`; a catalog entry at `/settings/lyrics-sources/store/item`.

- **Store page.** `PageScaffold` titled "Plugin store", content at most 720 px wide. Top to bottom: error banner (`errorContainer`, only while a repository failed: one repo names it and the reason, several show a count, both with Try again), search field, source chips (a horizontal scroll row, shown from two sources), then the sections Updates, Installed, Not installed as titled cards (title with count; Updates has the text button "Update all"). - **Rows.** `ListTile` with a 40 px rounded icon (the installed package's icon, else the catalog icon, else the extension icon), name, and the repository name or "From file"; an update row adds the version change after the repository name (`repo · v1 → v2`, from `lyricsStoreUpdateVersions`). One icon button on the right: update (primary), uninstall or install (primary). It has a tooltip and the same semantic label. While that work runs it becomes a 20 px spinner (labelled "Working") and cannot be tapped again. Tapping the row opens the plugin.
- **Install is immediate.** No confirmation. The snackbar "Installed (name)" with Undo appears only for a new or revived plugin, never for an update (undo would uninstall a plugin the user already had). Install problems open a dialog ("Could not install" with the reasons in a bordered box, "Package does not match the list" with what differs and Refresh & try again, "Needs a newer Kanaru"); when the screen is already closed, an error snackbar says the same instead, and an unexpected error shows a short "Something went wrong" snackbar. "No newer version" is quiet. Uninstall says "Uninstalled" only when something was removed; a plugin already gone gets an info snackbar.
- **Repository page.** Rows show name, URL and a trash can only; a repository whose last fetch failed has a red "!" circle with the reason as its tooltip. The "+" floating button sits at the bottom right and the list keeps 88 px of bottom padding so it never covers the last trash can. Removing asks first and says installed plugins stay but stop getting updates.
- **Add repository dialog.** One URL field and Cancel / Add, no explanatory text. While adding, the field and Cancel are disabled and Add shows a spinner and "Loading…"; the dialog cannot be dismissed until the answer. A failure shows its text under the field and clears when the user edits it.
- **Update banner.** On the page of an installed plugin whose repository lists a newer version (`lib/features/lyrics_sources/plugin_update_banner.dart`): a `primaryContainer` rounded bar above the info section reading "New version v(N)" with a filled "Update" button; nothing for a plugin from a file or a removed repository. While the update runs (started here or elsewhere) the button is disabled and shows a 16 px spinner labelled "Working". Success is a snackbar with the new version; a failure is an error snackbar "Could not update (name)" with the reason on a second line. When the package no longer matches the list (catalog mismatch) the snackbar has a "Refresh list" action that only refreshes the repository; the user taps Update again. Other failures have no action.
- **Texts** come from the `lyricsStore…` keys in `lib/l10n/`.

## Cover art

- Decode sizes are bucketed to 64, 128, 256 and 512 px (`shared/widgets/cover_art.dart`). Images are never decoded at full size in lists.
- `gaplessPlayback` is on for covers so they do not flash between tracks.
- Missing artwork shows a placeholder: a solid color chosen from a stable FNV hash of the album or artist name (`shared/stable_hash.dart`, `shared/widgets/placeholder_colors.dart`). The same name always gets the same color.
- Artist avatars (list, grid, Home, artist page header) show the cover of the artist's first album that has one, in artist page order: albums the artist owns before those it appears on, then year (unknown last), then title (`core/database/artist_cover_queries.dart`). Without any album cover they show the first letter on the same placeholder color.

## States

| State | Component | Rule |
|---|---|---|
| Library unavailable | Library browse body | Message that the library could not open; playback still works. |
| No roots | Library browse body | Empty state with the action to add a folder. |
| Keys updating | `library_keys_updating.dart` | "Updating library" with progress after a sort-rule change. Playback is not affected. |
| Loading | `library_loading.dart`, `MinBusyBuilder` | `MinBusyBuilder` keeps the busy state on for a minimum time, so a short task does not flash its indicator. |
| Empty | `EmptyState` (`shared/widgets/empty_state.dart`) | Icon, one sentence, optional action. |
| Scan finished | Snack bar | Result summary with counts; not a dialog. Every notice is a snackbar card with a status icon (see Snackbars). |
| Playback unavailable | `PlaybackUnavailableBanner` | Library-only mode. Pressing play reports one error and stays paused. |
| Track failed | Player error stream | Playback skips to the next track; a queue where every track fails stops (PLAY-13). |

Home uses `EmptyState` ("Your library is empty") only when the library has no song or cannot be opened. Favorites uses `EmptyState` only before the first like or when its playlist is empty.

## Settings

- Single column, at most 720 px wide, grouped in six sections, in this order: Appearance (theme, language, title bar, display options such as colors from the cover), Library (music folders, excluded folders, scan options and filters, folder watching, rescan at start, rescan), Lyrics (prefer embedded lyrics, online lookup, LRCLIB permission, saved lyrics, lyrics translation), Backup and restore (placeholder), Advanced (listen history, log folder, playback with the output device and ReplayGain, interface), About (repository, license). Options that are stored but not built yet carry a coming-soon badge.
- Every row has a hint line under its title that says what the option does; keep it to one sentence. A row that needs a restart replaces its hint with "Applies after restart" until the value is changed back.
- Rows: label on the left, control on the right. Below 560 px the control moves below the label.
- Library folder rows have only a trash button, faded in while the pointer is over the row or focus is inside it (it stays in the tree, so Tab reaches it and the row does not reflow). A missing folder keeps a red button visible.
- Options that are not wired yet are shown as "Coming soon" rows (`SettingRow.comingSoon` or `SettingsChipsRow`): disabled colors, a badge after the title, the saved value shown, and no tap or focus reaches the control. Real rows come first in each section; the coming soon rows follow. Whoever wires an option removes `comingSoon` and passes a callback. Numeric options are dropdowns of preset values (`settings_number_presets.dart`); a stored value outside the presets is added to the list.
- Choices use `setting_choice.dart`: a segmented button when there is room, a dropdown in a compact row.
- Language choices: system, English, Vietnamese. The title bar choice (kanaru, system, none) needs a restart; the screen says so.
- A save warning (`settings_save_warning.dart`) appears when settings cannot be saved.

## Lyrics sources pages

Sub-pages of Settings (`/settings/lyrics-sources`, `/settings/lyrics-sources/plugin/:installId`, and the plugin store under `/settings/lyrics-sources/store`), opened from the first row of the Lyrics section ("Lyrics sources", subtitle: names of the enabled sources in order and how many are on). They sit in the Settings branch, so the sidebar keeps Settings lit and Back returns to Settings. Code: `features/lyrics_sources/` (sources and plugin pages) and `features/lyrics_plugin_store/` (store pages).

- **Sources page.** A 720 px column under a page title with a ⋮ menu (Open log folder, Plugin writing guide). An info card explains the order (enabled sources are tried top to bottom; Choose lyrics searches all of them). The "Plugin store" button opens the store. One reorderable list holds LRCLIB (badge "Built in", switch and drag only, no page) and the installed plugins. A row: drag handle, 40 px icon (the plugin's `icon.png`, else a default icon), name, subline "author (self-declared) · vN · File: x.zip or Repo: name", the hosts, and a switch. Tapping a plugin row opens its page. With no plugin installed, a hint under LRCLIB points to the store.
- **Reorder by keyboard and screen reader.** The handle starts a drag at once. A focused handle takes Alt + Up and Alt + Down; Flutter's list adds "Move up / down / to start / to end" actions to each row for screen readers. A dropped order is shown at once, before the database answers.
- **Plugin page.** Title bar: "Plugin details" (the name shows once, in the header card) and a trash button (tooltip and semantics "Uninstall plugin"); no ⋮ menu and no uninstall button at the end of the page. Then the enable switch (far from the trash), "Details" (source, the hosts it can connect to, install date, description; the internal install id is never shown), "Plugin settings" built from the manifest (text, number with a number keyboard and a check, secret hidden with a reveal toggle, select, toggle; each saves on Enter, on leaving the field or on change, and a refused save says why in a snackbar) and "Data" (the plugin's own storage and the lyrics saved from it, each with Delete after a confirm). A plugin removed elsewhere shows "no longer installed" and a way back.
- **Secrets.** A secret field is never filled with the saved value: it shows a dotted hint and "Saved in the system keyring" when one is stored, and a remove button. Without a system keyring the page shows the keyring warning instead (file or memory storage). A locked keyring on save says to unlock it or restart Kanaru.
- **Uninstall dialog.** One dialog (`lib/shared/lyrics_plugins/plugin_uninstall_dialog.dart`) for the plugin page and the store: "Uninstall <name>?" with two boxes: "Will be deleted" (code, settings including secrets in the keyring when the plugin has any, its own storage with its size) and "Kept" (saved and pinned lyrics from the source with their count, `.lrc` files already written). Confirming returns to the sources page with a snackbar "Uninstalled <name>".
- **Install failures.** `lib/shared/lyrics_plugins/plugin_failure_text.dart` (with `plugin_problem_text.dart` for package problems) maps every install or update outcome (each package problem, each update refusal, an unavailable keyring, a plugin already gone) to text, and the store's `install_problem_dialog.dart` shows them as "Could not install" with a "Reasons" box. The Sources and store pages share this text.

## Context modal

One framework for item menus (`lib/shared/widgets/context_modal/`, opened with `showContextModal`). It knows nothing about songs: the caller passes a root `ContextModalPage` whose body is a list of `ContextModalAction` specs (`contextModalSections` joins groups with dividers; a caller prepends context groups such as queue or playlist). No providers are read inside it.

- **Wide**: centered dialog, 400 px wide on every page, at most `min(640, height - 48)` tall, radius 28, scrim 45 %. **Narrow** (below 600 px): full-width bottom sheet, radius 28 on top, drag handle, at most 85 % of the height. Only the handle drags: past 25 % of the sheet height or a fast fling closes it, so the body keeps its own scrolling.
- **Pages** are a stack (`nav.push`, `nav.pop`, `nav.close`). A change slides 24 px and fades over 200 ms; with reduced motion the page swaps at once. Sub-pages use `ContextModalTopBar` (back arrow, title, icon buttons).
- **Rows** show an icon, label and one ellipsized subtitle line, then optional trailing icon buttons (tooltip required), a chevron when the row opens a page, or a chevron that rotates when it folds chips. `destructive` uses the error color. `comingSoon` dims the row, adds a "Coming soon" badge, takes no focus, and a click shows an info snackbar. `premium` is kept in the spec but not drawn until licensing exists.
- **Chips**: a horizontal strip in the dialog (mouse wheel scrolls it sideways, edges fade), wrapped lines in the sheet (at most 116 px, scrolls).
- **Edges**: scrollbars are hidden; the top and bottom 28 px fade only while there is more content in that direction (`FadeEdgeScrollView`).
- **Keys**: Esc goes back one page and closes at the first; Backspace goes back and does nothing at the first (and is left to a focused text field). Up and Down move focus between rows, Enter and Space activate. Focus lands on the first row only when the modal was opened from the keyboard (Menu, Shift+F10) or after keyboard use inside it (Tab, arrows, Enter, Space); right click, long press, the ⋮ button and mouse clicks leave no focus ring. The first Tab or arrow with nothing focused lands on the first row. Closing returns focus to where it was.
- **Accessibility**: the modal is a named route; rows are buttons with label and subtitle; a coming-soon row announces "Coming soon".

## Song modal

The song's context modal (`lib/shared/song_modal/`, opened by `openSongModal`; the dialog is named "Song options"). It opens at once from a right click, a long press, the Menu key or Shift+F10 on a song row or card, or from the ⋮ button; the favorite and the links load while it is open and their rows are greyed out until then.

- **⋮ button**: on list rows only (`SongTile`, through the `more` slot of `SongRowView`, after the heart), 36 px, tooltip and semantics "More options", in the focus order. Always visible: dimmer at rest, full while the row is hovered or focused. Cards (`SongGridTile`, `HomeTrackCard`) have none. A row with no queue handler has neither the button nor the modal.
- **Header**: cover, artists line, title, album ("Unknown album" when none). Tapping it (it has a chevron) opens the Song info page; the actions page has no Song info row.
- **Rows**: screen-specific actions first (`extraActions`), then Go to album (left out on the album's own page, greyed "No album" without one), Go to artist (greyed without one; several artists fold name chips, open below 4 artists), Go to album artist (only when the album's artists with a page are not all the song's artists), Go to folder with a trailing Show in file manager button (both shown on every screen, the folder's own page included, and left out only for a song with no local path); then Add to playlist, Add to / Remove from favorites (hidden without a library), Edit tags (coming soon), Advanced. Footer: Play next and Add to queue, `bodyLarge` text like the rows; each button is an ink well filling its whole half of the footer, so hover and ink cover the full cell.
- **Song info page** (`song_modal/info/`): top bar with back, an eye (shows or hides the fields a song has no value for; kept as `display.songInfoShowUnknown`, off by default), a heart (the modal stays open) and a disabled "Play the best part · coming soon" button. Below, a 136 px cover with the play count, first listened and last listened dates ("Never played" at 0), then the groups Tags, Audio and File (File only for a song with a local path). Each field is one full-width row with a thin divider (`Divider`, height 1) between the rows of a group; the row reads "Label: value" (`bodyMedium`, label in normal weight and `onSurfaceVariant`, value `w500` in `onSurface`) and wraps from the start of the line. The release date and its chips are one row: the chips continue on the date's line and wrap under it only when the row is narrow. The whole row, edge to edge, is the hover and tap target (click cursor); long unbroken text such as a path wraps anywhere (zero-width spaces, display only). Tapping the row copies its value (the shown text for formatted fields such as duration, format and language name; the stored value for the rest) and shows "Copied: ...", tooltip "Copy"; an unknown field reads "Unknown" in italics and is not copyable. Release date shows the tag as written (the indexed year until it is read), with chips for the written-out date (as precise as the tag) and "N years ago". Everything comes from the library row, no file is read; while it loads the page shows grey bars, and a song removed from the library shows a message with a way back.
- **Lyrics card** (`song_modal/lyrics/`), between the Tags and Audio groups of a song with a local path: a `surfaceContainer` card (radius 16) with the lyrics icon, "Lyrics", a source chip (".lrc file", "Embedded" or "Online · name") and a "Synced" chip for timed lyrics. The preview is the first 8 lines (never with times; an empty line is a small gap; long unbroken text wraps anywhere); above 6 lines it sits in a box 8 lines high that fades at the bottom, with a "View all · N lines" button (N counts lines with words, ICU plural in `en` and `vi`). While the lyrics are read it shows 6 grey bars that pulse, still under reduced motion. A song with no lyrics shows the card ("No lyrics" and a Find online button that closes the modal and opens the search) only while the eye shows unknown fields. It reads saved data only and never starts an online search.
- **Full lyrics page**: back, "Lyrics · title" (one line, ellipsis), a clock button for each line's time as `mm:ss` (synced lyrics only; kept while the page is open) and a copy button (plain text without times, snackbar "Lyrics copied"). Rows are built as they scroll, so very long lyrics stay cheap. Back returns to the same scroll position on the Song info page (`ContextModalPage.scrollController` with `RememberedScrollController`).
- **Advanced page**: Find lyrics online (needs a library and a local file), Remove from library and Delete file (coming soon).
- Every action that navigates, opens a dialog or likes a song closes the modal first, then runs through the `TrackMenuRunner` captured before it opened, so a row rebuilt away by a rescan changes nothing and a song gone from the library says so in a snackbar.

## Motion and reduced motion

| Motion | Duration | Reduced motion |
|---|---|---|
| Page transition | 300 ms (reverse 220 ms) | Fade only (`app/page_transition.dart`) |
| Branch transition | 300 ms | Fade only (`app/shell/branch_transition_container.dart`) |
| Sidebar collapse | 400 ms | Not gated in the code found by grep. Known gap; see below. |
| Queue sheet | 400 ms | Checked (`queue_sheet_host.dart`) |
| Now Playing slide | 500 ms | Checked (`now_playing_overlay.dart`) |
| Auto-hide fade | 100 to 150 ms | Not gated |
| Now Playing cover gradient fade | 300 ms | Instant (`cover_tint_background.dart`) |
| Context modal page change | 200 ms slide 24 px + fade (route fade 140 ms) | Instant (`context_modal_shell.dart`) |
| Waveform fade-in | 200 ms, bars over the flat track | Instant (`waveform_seek_track.dart`) |
| Now Playing mode switch | 300 ms crossfade, the outgoing body is not remounted and ignores pointer and focus while it fades | Checked (`now_playing_wide_layout.dart`) (lyrics never cause a switch) |

Reduced motion comes from the platform setting, or from Settings → Appearance → Animations turned off: the app's builder (`lib/app/app.dart`) then sets `MediaQuery.disableAnimations` for every page, dialog and menu, and the Now Playing gradient fade is instant too. The theme change itself (`themeAnimationDuration`) is always instant. Turned on, the platform setting decides. Every new animation must check `MediaQuery.disableAnimationsOf`, never the setting itself. The sidebar collapse does not appear to check it yet; treat that as a bug to fix, not a pattern to copy.

**Text size.** Settings → Appearance → Text size (80 % to 150 %) multiplies the system's text scale in the same builder (`appTextScaler`). Enlarging stops at 2× (or at the system's scale when that is larger, so a large accessibility size is never undone). Layouts size rows and grid tiles from `MediaQuery.textScalerOf`, never from fixed heights.

## Focus, keyboard and accessibility

| Key | Action | Where |
|---|---|---|
| Space | Play or pause | App-wide, even when a button has focus; not in text fields or when there is nothing to control |
| Left, Right | Seek minus or plus 5 s | App-wide, same exceptions |
| Ctrl+S | Toggle shuffle | App-wide |
| Ctrl+R | Cycle repeat (off, all, all shuffled, one) | App-wide |
| V | Cycle the Now Playing view mode | Wide Now Playing only; no modifier; not in a text field or while the volume popup or a header menu is open |
| L | Open the lyrics source menu (focus on its first item) | Wide and narrow Now Playing, not in Cover only; no modifier; not in a text field or while a header popup or menu is open; nothing when there is no source button |
| Esc | Close overlay, sheet or drawer | Now Playing, queue sheet, drawer |
| Esc, Backspace | Back one page; Esc also closes at the first page | Context modal |
| Ctrl+F | Focus the top bar search field and select its text | App-wide; a page filter box takes it first, and pressing it again inside that box goes to the top bar; nothing while a dialog, menu or Now Playing is open |
| / | Same as Ctrl+F, never opens a page filter | Only when no text input has focus; nothing while a dialog, menu or Now Playing is open |
| Mouse back, forward | History back, forward | Anywhere |

- Keys are handled by `features/player/player_shortcuts.dart`; Ctrl+F and `/` by `app/shell/top_bar_search_shortcuts.dart`, a hardware keyboard handler that returns true only when it acts, so the other keys above still work.
- Not implemented yet (SYS-03): Ctrl+Left and Ctrl+Right for track change, Up and Down for volume. Scroll over the volume button already changes volume.
- Sliders expose slider semantics.
- Focus is restored after an overlay or sheet closes.
- Contrast: use theme `on*` color pairs. Do not place text on artwork without a scrim (guideline, not enforced by a test).
- Screen reader coverage is partial (UI-11).
- Every row with a right-click menu opens the same menu from the keyboard (Menu key or Shift+F10 while focus is in the row), anchored on the row; Esc closes it and focus returns to the row (`shared/widgets/menu_keyboard_region.dart`). Queue rows have a menu too: the heart (add a library song to Favorites, or take any song out) and remove.
